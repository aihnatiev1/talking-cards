## 0. Одне рішення, з якого випливає решта: «стіл»

Метафора екрана — **картки лежать на килимку на столі, а Bloom сидить поруч і дивиться**. Три шари глибини:

```
кімната (папір)  <  килимок (mat)  <  поле сорочки (wash)  <  печатка (seal)
```

Уся колірна система — одна **тема дошки** (`BoardTheme`), похідна від одного кольору. Один painter і одна формула, не 21 малюнок.

### BoardTheme

```
base  = pack.color, якщо всі widget.cards належать widget.pack (вхід з CardsScreen)
      = DT.mint (#6BCB77) для змішаної дошки з ігрового таба (колір плитки «Знайди пару» у табі)

seal  = HSL(base) з обмеженням  L ∈ [0.40, 0.58],  S ∈ [0.45, 0.85]
        світлі (жовтий #FFD93D → ≈#EFCB39) темнішають — кремовий силует на печатці читається ≥ 3:1;
        глибокі (#004D40 «Щ» → ≈#0FBD9F; #546E7A «Ч» → ≈#38789A) світлішають — wash не сірий.
ink   = DT.onTint(seal)                    штрихи рамки, стібки килимка
paper = #FBF4E6  (новий токен DT.paper)     папір карток; менш персиковий за DT.bgCard
wash  = lerp(seal, paper, 0.80)            поле сорочки (≈20 % теми)
mat   = lerp(seal, bg,    0.86)            килимок
bg    = DT.bgWarm #FFFBF0                   кімната (замість #FAFAFF)
```

Приклади base → seal: Тваринки #4ECDC4 → без змін; Транспорт #0984E3 → ≈#1284D9; Емоції #FF6B9D → ≈#EF3975; mint → ≈#5FC66C.

Реалізація: `lib/utils/board_theme.dart`, value-object `BoardTheme.of(pack, cards)`; `HSLColor.fromColor(...).withLightness(...).withSaturation(...)`.

## 1. Сорочка карти

### Що на ній

Сорочка = **зворот паперової картки з печаткою**. Не патерн з емодзі, не іконка пака, не фото-текстура. Один `CustomPainter` (`CardBackPainter(theme)`), проєктний простір 100×110, масштабується під плитку. Координати — у % ширини:

```
┌──────────────────────────┐
│ ╭──────────────────────╮ │   зовнішня рамка: ink α.55, 2.2dp, «олівцева» лінія
│ │ ╭──────────────────╮ │ │   внутрішня рамка: ink α.30, 1.2dp
│ │ │ ★              · │ │ │   дудли: seal α.30, 7 штук, ФІКСОВАНІ позиції
│ │ │                  │ │ │
│ │ │      ╭────╮      │ │ │
│ │ │     ( (\/) )     │ │ │   печатка Ø 34 %: коло seal; силует Bloom (голова + 2 вуха) — paper
│ │ │     ( ◠  ◠ )     │ │ │   очі-дужки і ніс на силуеті — seal
│ │ │      ╰────╯      │ │ │
│ │ │ ·            ♡   │ │ │
│ │ │       ·          │ │ │
│ │ ╰──────────────────╯ │ │
│ ╰──────────────────────╯ │
└──────────────────────────┘
  поле: wash. Радіус кутів: clamp(tileW × 0.13, 14, 22).
  тінь (BoxDecoration, поза painter'ом): seal α.28 offset(0,4) blur 0  +  seal α.12 offset(0,8) blur 14
  — та ж «наліпка з твердим краєм», що на плитках ігрового таба (_BigGameTile).
```

1. **Поле** — RRect, заливка `wash`. Не білий, не градієнт.
2. **Подвійна рамка** — inset 7 % і 11 %. Лінія не векторно-рівна: кожна сторона з 12 сегментів, вершини зсунуті на детермінований ±0.6dp (синус із фіксованою фазою) — «намальовано олівцем» без асета.
3. **Дудли** — фіксований набір із 7 мотивів у рамковій смузі: 2 зірки (6 %), 3 крапки (3 %), 1 сердечко (5 %), 1 завиток (7 %); `seal` α.30. Ті ж мотиви, що літають навкруг яблука і скейта на ілюстраціях.
4. **Печатка** — коло Ø 34 %, заливка `seal`, кремовий кант 2dp (`paper` α.9). Усередині силует Bloom: голова (овал 58 % діаметра), два вуха (RRect, нахил ±0.22 як у `_BloomPainter._paintEar`), заливка `paper`; очі — дві дужки `seal` stroke 6 % діаметра; носик — трикутник `seal`. Три фігури, читається на 60dp і на 300dp.
5. **Фактура паперу** — хвиля 3: tileable 128×128 alpha-noise webp (~6 KB), `ImageShader` з `TileMode.repeated`, α.06, `BlendMode.multiply`. Один асет на сорочку і килимок.

### Чому не іконка пака і не патерн з емодзі

- Змішана дошка з таба не має «пака».
- Емодзі — системна графіка, різна на iOS/Android, чужа акварелі (аудит №16).
- 9 паків мають літери замість іконок; літера на сорочці для 1–3 років — шум.
- Колір теми вже розрізняє паки, а печатка з персонажем дає впізнаваність бренду.

### Абсолютна вимога: усі сорочки піксельно однакові

Жодного `Random`, жодного seed від `tileId`. Трирічка за два раунди навчиться відрізняти карти по зсунутій зірочці — і гра зламається. Один painter, одні координати, `shouldRepaint` лише при зміні `theme`. Кожна плитка — `RepaintBoundary`.

### Чи «дихає» сорочка у спокої

**Ні, не циклічно.** Власник просив «ледь помітно, щоб дошка не була мертвою», але аудит п. 12 (рішення власника) вимагає: вступний акцент, потім спокій, а рух — тільки на активній цілі. Нескінченний цикл на випадкових картах — саме те, що п. 12 забороняє. Тому:

- **Поки дитина грає (тап ≤ T1 тому) — дошка абсолютно нерухома.** Жива вона за рахунок глибини: тверда тінь, печатка, фактура, килимок.
- **Вступний акцент** — здача карт (§4), ≤ 720 мс, один раз на раунд.
- **Рух з'являється тоді, коли потрібна дія** — двоступенева підказка на бездіяльність (§6): ступінь 1 «запрошення» — одна закрита карта злегка ворушиться (scale 1.00 → 1.03 → 1.00 + Z 0 → −1.5° → +1.5° → 0, 320 мс, без звуку); ступінь 2 «підказка» — ворушиться саме карта-пара, зі звуком і реакцією Bloom. Це transform над `RepaintBoundary`; painter не перемальовується.
- Єдиний персонаж, який дихає, — Bloom (§3), і він не поверх карт.

Так виконуються обидва: «дошка не мертва» (рух є, але у момент, коли він підказує дію) і п. 12.

## 2. Сцена

### Кімната

Фон `DT.bgWarm` #FFFBF0 — той же папір, що в табах. Без градієнтів. Хвиля 3: 4–5 бляклих (ink α.07) великих дудлів по кутах кімнати (сонечко, хмарка, зірка), поза килимком — ніколи під картами.

### Килимок (mat)

`BoardMatPainter(theme)` у Stack **під** GridView:

- прямокутник = rect дошки, роздутий на 16dp (телефон) / 24dp (планшет), радіус 32;
- заливка `mat`;
- «стібки»: пунктир ink α.25, 2dp, dash 8 / gap 6 по контуру RRect (`Path.computeMetrics` + `extractPath`);
- 4 кутові дудли seal α.18 (зірка, сердечко), 10dp;
- на телефоні килимок може бути ширшим за екран — **не затискати**, хай виходить за край: «стіл більший за екран».

Килимок не конкурує з картами (14 % теми проти 20 % + печатка + рамка). Статичний, `RepaintBoundary`, `shouldRepaint` false.

### Розкладка: де сидить Bloom (п. 18: не поверх карт)

Дошка вже вміщується в будь-який бокс (`LayoutBuilder`, логіку не чіпаємо). Ми лишень **вирішуємо, який бокс їй віддати**:

```
1) Виміряти дошку за поточною формулою на повному боксі → boardW, boardH.
2) spareW = box.maxWidth − boardW.
   spareW ≥ 216 → режим «ПОРУЧ»: юніт [зона Bloom 200dp | gap 16 | дошка], юніт центрується.
                  Bloom 160dp (112 на тісному планшеті-portrait), ліворуч, вирівняний по нижньому краю
                  килимка, перекриває його на 12dp («сперся на килимок»). Карт не торкається.
   інакше       → режим «ЗНИЗУ»: дошці віддається box.maxHeight − 112; смуга 112 = 8 gap + 88 Bloom + 16 низ.
                  Bloom 88dp, лівий край килимка + 8dp. Під дошкою, не на ній.
```

Bloom **завжди ліворуч**: права рука дитини, що тягнеться до карт, не закриває його реакцій; діагональ із пігулкою лічильника праворуч угорі.

### Лице карти (`_FrontFace`)

- **Стан «зібрано»** — без зеленого #4CAF50 (немає в палітрі; для дитини зелене ≠ «правильно»): рамка 3dp `seal`, зірка-наліпка у правому верхньому куті (painter: 5-кутна зірка `DT.sunBurst` з контуром ink, 18 % ширини, виступає на 4dp за край), тінь плоска `seal α.18 offset(0,2) blur 0` — карта «лягла на стіл». Картинка у повному кольорі: галерея того, що дитина знайшла. Пари **лишаються на дошці** (п. 20).
- Тінь відкритої незібраної карти — така ж, як у сорочки (тема), не від `colorAccent`.

### Верхня панель

- Кнопка назад — не чіпаємо (§7).
- Заголовок «Знайди пару» 16sp Roboto → `DT.h2` (Nunito 800, 18sp, textPrimary) — текст для батька. Long-press на заголовку — батьківський вибір поля (§6).
- Пігулка `0/3` — не чіпаємо (§7).
- Крапки прогресу → зірки (§4), та ж позиція.

### Темна тема

Апка має перемикач у батьківському дашборді. Правило: **темніє кімната, не предмети**. `bg` → #2A2420, `mat = lerp(seal, bg, 0.80)`, стібки `paper α.25`, заголовок білий. Карти, сорочки, Bloom — без змін (фізичні предмети не темніють; контраст ілюстрацій зберігається).

## 3. Bloom у грі

Bloom — `CustomPainter`, простір 120×120. Нові емоції — нові гілки в `_BloomPainter`. Painter статичний; рух — трансформи.

### Два правила з п. 18

1. **Не поверх навчального об'єкта.** Bloom у власній зоні (§2), ніколи не перекриває карту, килимок під ним не має карт. Реакції — на місці (стрибок ≤ 14dp вгору, нахил ≤ 6°) — зона розрахована з запасом 16dp.
2. **Не блокує старт.** Привітання (`waving`) іде паралельно зі здачею; інструкція грає, а не чекається; перший тап приймається, як тільки карта приземлилася (§4). Жодного «дивись на мене, потім грай».

Функціональні сцени (п. 18): привітався (вхід), почекав (`curious` між картами), порадів **конкретному** успіху (стрибок саме у момент пари; при перемозі — оверлей), попрощався — поза цим екраном (оверлей «Готово»; кнопка назад має лишатися миттєвою).

### Розміщення

§2: ліворуч, «поруч» (160dp) або «знизу» (88dp). `interactive: true`, але обробник тапу — у грі (нижче).

### Нові емоції для painter'а

**`curious`** («Хм? Де ж пара?»)
- очі **відкриті** — кола `_ink` r 3.4 у (46,55) і (74,55); відблиск — біле коло r 1.1 у (44.8,53.8) і (72.8,53.8);
- рот — маленьке «о»: овал 4×3 stroke 2.0 `_ink`, центр (60,74);
- ліве вухо нахилене вперед сильніше: rotate −0.42 (замість −0.22); праве як є;
- лапи обидві внизу; щічки без змін.
- Поза (трансформ): нахил усього Bloom 6°, 220 мс `easeOut`.

**`excited`** («Ура, пара!»)
- очі — щасливі дужки, підняті на 3 і ширші: `moveTo(38,54) quadTo(46,46, 54,54)` і дзеркально `(66,54)-(74,46)-(82,54)`, stroke 3.2;
- рот — відкрита усмішка: заповнений півеліпс `_ink` від (52,71) до (68,71), глибина 8; язичок — овал 6×3 `_earInside` у (60,76);

### Idle

- Дихання: scale 1.00 ↔ 1.02 навколо `Alignment.bottomCenter`, синус, період 2.6 с. Це єдина постійна анімація на екрані. Обґрунтування проти п. 12: Bloom — персонаж, а не декор; нерухомий painter-персонаж читається як наліпка, дихання — його «стан слухання». Вимкнено при reduce-motion; поставлено на паузу під час анімацій матчу/промаху (щоб на екрані було ≤ 2 рухи).
- Хвиля 3: кожні ~5 с одне вухо смикається на 8° (220 мс) — потребує параметра `earTilt` у painter'і.

## 4. Анімації і політика руху

### Політика (п. 11, 12, 13)

- **Реакція на дотик — 0–140 мс**: на tap-down одразу `DT.pressScale` (.96) за `DT.pressMs` (140) + `flip` SFX + light haptic. Дитина отримує три відгуки до того, як карта почала обертатися.
- **Переходи — 220–320 мс.** Це стискає мою типову норму 300–500 для малюків до верхньої межі аудиту; беремо 320 як спільну точку. Ефекти-частинки (іскри) — не переходи, їм дозволено до 500 мс, і вони завершуються самі (п. 12: «велике конфеті завершується»).
- **Переходи не затримують ані звук, ані тапи.** Слово стартує на 120 мс після тапу (карта ще обертається). Тапи приймаються завжди, крім карт, що ще летять під час здачі, і паузи промаху (яку тап скорочує — нижче).
- **Вступний акцент, потім спокій** (п. 12): здача карт — єдина «вистава». Далі рухаються лише те, що дитина торкнула, і підказка на бездіяльність.
- **Reduce-motion** (п. 13): одна точка істини — `lib/utils/motion.dart`: `bool reduceMotion(BuildContext)` = `MediaQuery.disableAnimationsOf(context)` і `Duration motion(BuildContext, int ms)` → 0 при reduce. При reduce дозволені лише зміни кольору/стану та opacity-fade ≤ 120 мс; жодних переміщень, масштабів, обертань, частинок. Кожен рядок таблиці нижче має колонку «reduce-motion». Цю утиліту потім можуть підхопити інші екрани (аудит хоче єдину політику) — але тут ми лише її створюємо і застосовуємо в цій грі.

### Здача (вступний акцент; початок раунду і «Ще раз»)

Карти вилітають **з позиції Bloom** у слоти: старт scale 0.6, rotate −8°, α 0 → у слоті scale 1.0, rotate 0, α 1; 280 мс `easeOutBack`; stagger `min(40 мс, 440 / tiles)`; повний час ≤ 720 мс навіть для 16 карт. Карта, що приземлилася, **одразу тапабельна** (блокуються лише ті, що летять). Один `deal` swoosh на t = 0. Bloom `waving` паралельно. При рестарті з оверлею — просто здача (fly-back неможливий: оверлей закриває дошку).
Reduce-motion: карти на місцях одразу, fade 120 мс.

### Знайомство (опція, п. 20)

Після здачі всі карти лежать **лицем догори** 2.0 с (level 1) / 1.5 с (level 2, перший раунд сесії), потім лягають по черзі: stagger 60 мс, кожна 320 мс. Без озвучки (6 слів підряд — каша). **Будь-який тап під час знайомства** миттєво кладе всі карти і застосовується до тапнутої — ніхто не чекає (п. 18). Увімкнення — §6.
Reduce-motion: карти показані лицем догори той самий час, потім міняються на сорочку через fade 120 мс.

### Переворот

| Крок | Час | Що |
|---|---|---|
| tap-down | 0 | `pressScale` .96 (140 мс `easeOut`), `flip` SFX, light haptic |

| підйом | 0–320 | scale .96 → 1.06 (пік на 160) → 1.00; тінь offset (0,4) → (0,14), blur 0 → 18, α .28 → .18 і назад — карта відривається від столу |

### Тап по вже відкритій або зібраній карті

Зараз — мовчазний `return`. Стає: bounce scale 1.00 → 1.04 → 1.00, 180 мс + **повтор слова** (якщо `AudioService.isSpeaking` false) + light haptic. І правило №2, і безкоштовний мовний повтор: тицьнув у картинку — почув слово. Подвійний тап = одинарний.
Reduce-motion: тільки слово + haptic.

### Промах

- Утримання за віком (§6): 1400 / 1200 / 900 / 800 мс — **і не раніше, ніж закінчиться слово другої карти** (`isSpeaking` → false + 200 мс). Зараз 900 мс фіксовано і слово може обрізатися.
- Повернення: `rotateY` π → 0 за 320 мс `easeInOutCubic`, **без підйому** (карти лягають, не злітають), scale 1.00 → 0.97 → 1.00; друга карта стартує на +60 мс.
- `miss` SFX на початку повернення першої, vol .4. Haptic `selectionClick` замість `mediumImpact` (середній буз на промаху відчувається як покарання).
- **Тап під час утримання**: зараз ігнорується. Стає: якщо минуло ≥ 500 мс — утримання завершується негайно, карти лягають, і **один** тап стоїть у черзі та застосовується після посадки (≤ 380 мс). Дитина відчуває, що її почули.
Reduce-motion: лице → сорочка через fade 120 мс.

### Прогрес: крапки → зірки

N контурних зірок (`ink` α.35, 16dp, painter) → заповнена `DT.sunBurst` з контуром `ink` при матчі, pop 220 мс `easeOutBack`. Ті самі зірки, що на картах — одна мова. Reduce-motion: заповнення миттєве.

### Перемога

Після послідовності матчу (t ≈ 600): «хвиля» по зібраних картах у порядку сітки — scale 1.00 → 1.05 → 1.00, 200 мс, stagger 30 мс (16 карт ≈ 650 мс); Bloom wobble. На 1200 мс — існуючий `showGameCelebration` (не чіпаємо), внутрішній Bloom гасне. Повноекранне конфеті — лише в оверлеї, і воно там уже є.
Reduce-motion: без хвилі; оверлей сам обробляє (у нього вже є перевірка).

### Продуктивність

`RepaintBoundary` на плитку, килимок, Bloom. Painter'и статичні. Усі рухи — трансформи. У спокої 1 тікер (дихання Bloom), під час підказки 2. Ніяких `BackdropFilter`/`ImageFilter.blur`. Іскри — ≤ 12 частинок в одному painter'і. Idle-таймери — `Timer` після першого кадру, не `repeat()` без перевірки reduce-motion, щоб `pumpAndSettle` у тестах не зависав.

### Варіації висоти без нових файлів (`setRelativePlaySpeed`)

- `flip`: випадково 0.94–1.06 — дванадцять переворотів не звучать як один семпл.
- `match`: **драбинка** — 1.00 для першої пари раунду, +0.06 за кожну наступну (1.06, 1.12, …): звук сам розповідає «ближче до кінця». На останній парі — верхня нота, за нею `tada` з оверлею.
- `bloom_tap`: 0.90–1.10.
- `nudge`: 1.0 на першій підказці, 0.94 на наступних — м'якше, не наполегливіше.

Реалізація: `playSfx` повертає після `_soloud.play(src, volume)`; додати необов'язковий параметр `speed` і після `play` викликати `_soloud.setRelativePlaySpeed(handle, speed)`.

### Правила

- Голос завжди зверху: SFX нормалізовані на пік −6 dBFS, граються ≤ .7; слово — 1.0. `playSfx` не чіпає `stop()` наратора (так уже є).
- Два SFX не ближче 80 мс — другий пропускається.
- `flip` (≤ 100 мс) закінчується до старту слова (120 мс).
- Формат WAV mono 44.1 кГц 16-біт, ≤ 60 KB кожен. `AudioService.playSfx(name)` приймає довільне ім'я — нового API, крім `speed`, не треба.
- Джерела: Kenney «Interface Sounds» / «UI Audio» (CC0); freesound.org з фільтром CC0 (`page flip short`, `kalimba single note`, `toy squeak`); або синтез numpy у `tools/` за прикладом v1. Не брати CC-BY — у дитячій апці атрибуцію нікуди подіти.

## 6. Складність: за впевненістю, за віком

Рішення власника (п. 20): «після 2 перемог» — недостатній сигнал. Перемога у меморі неминуча, вона не каже, чи було легко. Замість неї — **впевненість раунду**, три речі, які гра вже може порахувати, не показуючи дитині: промахи, підказки, чи грала дитина сама.

### Що рахуємо у раунді

```
misses  — кількість промахів
hints   — кількість показаних підказок ступеня 2 (§ нижче)

calm     = misses ≤ pairs   ∧  hints == 0        спокійне проходження
struggle = misses ≥ 2·pairs ∨  hints ≥ 2         важко
інакше   — нейтрально
```

Для 2-парної дошки випадкова гра дає ~1 промах — `calm` досяжний і для півторарічки, тобто ступінь усе ж росте. Час не рахуємо і не показуємо: жодних таймерів для ≤ 5 років.

### Правила ступеня

Ступені поля: **2 → 3 → 4 → 6 → 8** пар. Дошка росте **всередині сесії, без меню** — це і є механіка, яка лишається.

- **Вгору**: level 1–2 — після **2 спокійних раундів підряд** на поточному ступені; level 3–4 — після **1 спокійного**. Нейтральний раунд обнуляє серію, але не рухає ступінь.
- **Важко — лишаємось на знайомому полі.** `struggle` → ступінь той самий, серія спокійних обнуляється. Дитина бачить те ж поле, що щойно пройшла.
- **Тихе повернення**: 2 `struggle` підряд на ступені, до якого піднялися **в цій сесії**, → назад на попередній ступінь. Нижче стартового для рівня — ніколи. Нічого не показується і не озвучується; просто наступна здача менша. Для 1–3 років це непомітно; для 4–5 — м'якше, ніж застрягти.
- **Пам'ять комфорту** (хвиля 2): останній ступінь зі спокійним раундом зберігається per-profile (`ProfileService`-префікс, ключ `memory_comfort_tier`). Сесія стартує з `max(startTier(level), comfortTier)`, не вище стелі. Дитина не починає щодня з нуля.

### Вибір (п. 20: «або давати вибір»)

- **Дитині — неявний**: після спокійного раунду «Ще раз» здає більше поле; Bloom «пропонує» більше карт самою здачею. Якщо стало важко — поле тихо повертається. Це і є вибір, який 2-річка може зробити тілом, а не кнопкою.
- **Батькові — явний**: long-press на заголовку «Знайди пару» → маленький батьківський лист (стандартні 16sp): вибір поля 2 / 3 / 4 / 6 (/ 8) пар і перемикач «Показати картки спочатку» (знайомство). Діє до кінця сесії; авто-ступінь на цей час вимкнений. Без Parental Gate: це не налаштування, не покупка, не зовнішнє посилання — той самий клас дії, що тогл «Автогортання» у батьківському листі `cards_screen` (без гейту), і той самий батьківський жест (long-press), що на плитках паків.
- **Дитині 4–5 явний** (хвиля 3, необов'язково): перед раундом дві великі картинки-кнопки «мало карт / багато карт» (мініатюри дошок 2×2 і 3×3), 88dp. Тап по будь-якій — здача. Для level 1–3 не показується.

### Таблиця за віком

Вік — `ref.read(profileProvider).active?.level ?? 2` (1: 1–2 р., 2: 2–3, 3: 3–4, 4: 4–5). Зараз level читає лише аналітика і пейвол.

| level | Старт | Стеля | Вгору після | Утримання промаху | Знайомство | Підказка: T1 запрошення / T2 підказка | Тип підказки T2 |
|---|---|---|---|---|---|---|---|
| 1 (1–2) | **2 пари** (2×2) | 3 | 2 спокійних | 1400 мс | завжди, 2.0 с | 4 с / 7 с | **peek**: карта-пара повертається до ~110° на 500 мс (лице видно під кутом) і лягає, + `nudge`, Bloom `curious` |
| 2 (2–3) | 3 (2×3) | 4 | 2 спокійних | 1200 мс | 1-й раунд сесії, 1.5 с | 5 с / 9 с | похитування карти-пари: Z ±3°, 3 цикли, 320 мс + `nudge` |
| 3 (3–4) | 4 (3×3) | 6 | 1 спокійний | 900 мс | вимкнено (опція) | 8 с / 12 с | похитування |
| 4 (4–5) | 6 (3×4) | 8* | 1 спокійний | 800 мс | вимкнено (опція) | 10 с / 15 с, лише якщо ≥ 2 промахи в раунді | похитування |

\* 8 пар потребують `cols = 4` — зміна правила колонок у `LayoutBuilder` (не логіки вміщення). Хвиля 3, з дозволу власника; інакше стеля level 4 — 6 пар.

Пояснення:

- **2 пари для півторарічки** — не «замало». Робоча пам'ять у 14–20 міс. не тримає 6 позицій; гра для них — «переверни, побач картинку, почуй слово, Bloom радіє». 4 карти = перемога за ≤ 4 перевороти = цикл, який хочеться повторити 20 разів.
- **Підказка двоступенева** (це і є «рух підказує дію», п. 12): T1 — одна випадкова закрита карта злегка ворушиться без звуку («тут є що робити»); T2 — якщо відкрита одна карта, ворушиться саме її пара (peek для level 1), зі звуком і Bloom; якщо жодної — T2 = T1 зі звуком. Після 3 підказок без жодного тапу — стоп, Bloom лишається в idle (не докучати). Підказка **ніколи** не відкриває карту сама і не озвучує слово — слово дитина здобуває власним тапом. Тільки T2 рахується у `hints`.
- `pairCount` стає `int?`: `null` → зі level/комфорту; явне значення — override (тести, dev). `games_tab` і `cards_screen` перестають передавати 3/6 руками.
- **Затиснути ступінь до `pool.length`**: якщо в паку менше карт з аудіо, ніж пар, `take()` віддасть менше плиток, а лічильник чекатиме на неіснуючі — раунд не виграється ніколи.
- Аналітика (COPPA-безпечно, агрегати): `logEvent('memory_round', {level, pairs, misses, hints, calm})`, `logEvent('memory_tier_change', {from, to, reason: up|stay|back|parent})` — для калібрування порогів. Жодних ідентифікаторів.

2. `cols = 4` для 8 пар (level 4).
3. Hit-area кнопки назад 72dp без зміни вигляду.
4. Текст пігулки `ink` на `paper`.
5. Чи вважати батьківський вибір поля «налаштуванням» (тоді — `showParentalGate()`).
